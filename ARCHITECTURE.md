# Architecture

Bobber is a static, bilingual site for GitHub Pages. There is no bundler, framework, server, or build step: the repository is the deployable site. This document explains how the pieces fit together so a new maintainer can make changes without reverse-engineering the whole page.

## Page boot sequence

1. **Inline preference script (in `<head>`)** runs before the stylesheet. It reads `?lang=`, `localStorage`, and the system theme, then sets `data-theme`, `data-locale`, and `<html lang>` to avoid a flash of the wrong theme or language. It is deliberately storage-safe: blocked storage must not break a Spanish URL.
2. **`styles.css?v=…`** loads. The stylesheet is ordered from tokens through components to themes and print. See the map at the top of the file.
3. **Deferred scripts execute in document order.**
   - `scripts/pdf-reader.js` defines the in-page reader.
   - `data/resources.js` defines the printable catalog.
   - `data/content.js` (home page only) defines tips, pals, laundry-check copy, and quiz questions.
   - `data/pdf-meta.js` (home page only) is generated page counts/sizes/preview paths.
   - `data/translations.js` defines the Spanish interface dictionary.
   - `scripts/main.js` wires the page and calls `setLanguage()` once at boot.
4. **After `load`**, `setupPwa()` registers the versioned service worker when idle.

### Classic-script global scope

The browser scripts are classic deferred scripts, not ES modules. They share one global lexical scope. A duplicate top-level `const` in two files is a fatal `SyntaxError`, and a duplicate top-level function would silently overwrite the other. This happened during development once. Always run:

```bash
npm run check:globals
```

before adding a top-level name. Why not modules? The site is intentionally build-free and deploys the source files directly; classic scripts let the data files and reader load in a fixed order with simple `?v=` cache busting.

## Data contracts

### `data/resources.js`

```js
/** @type {Array<{
 *   title: string,
 *   category: "activity" | "poster" | "storybook",
 *   file: string,   // "pdfs/name.pdf"
 *   image: string   // thumbnail filename under assets/graphics/
 * }>} */
window.BOBBER_RESOURCES
```

Also exports `BOBBER_CATEGORY_LABELS` (singular badges) and `BOBBER_FILTER_LABELS` (plural filter buttons). `BOBBER_RESOURCE_TITLES_ES` must contain an entry for every resource title; `npm run check` and `scripts/check-site.ps1` enforce that.

### `data/pdf-meta.js`

Generated by `npm run update:pdf-meta`. Do not edit by hand.

```js
Record<"pdfs/name.pdf", {
  pages: number,
  bytes: number,     // print-quality file size shown on the card
  webFile?: string   // lightweight preview under pdfs/web/, when one exists
}>
```

### `data/content.js`

Home-page-only curated content, deep-frozen so accidental mutation fails loudly:

- `tips`: bilingual speech-bubble reminders
- `looks`: Bobber artwork for the lake-ready checklist
- `reactions`: checklist feedback
- `palCards`: printable trading-card details
- `gamePool`: quiz questions; every question must have exactly one `correct: true`

`npm run check:content` validates copy, image paths, and quiz answers.

### `data/translations.js`

A flat `Record<EnglishText, SpanishText>` used by the language toggle. Static text is captured once at boot and replaced by looking up its exact trimmed text. Dynamic widgets (resource cards, quiz, certificate, reader chrome) translate themselves in JavaScript. Add a new static sentence to this file, or it will remain English in Spanish mode.

## Language and theme

- **URL wins:** `?lang=es` overrides stored language, then the toggle updates the URL with `history.replaceState`.
- **Theme:** `bobber-theme` in `localStorage`, otherwise the system preference. The toggle updates `data-theme` and the `theme-color` meta.
- **Static translation:** `staticEnglishTextNodes` captures the authored English text once. `setLanguage()` swaps those nodes and then updates dynamic content and accessible names.
- **Card-level Spanish:** safety cards contain authored `.spanish-copy` blocks marked as draft. These are separate from the interface dictionary and still need fluent review.
- **Accessibility:** every language change must update the document language, page title/description, control labels, external-link suffixes, filter labels, card-detail labels, reader labels, and game/certificate copy.

## Library

Cards are created once per language. Search and category filters only toggle `hidden` on the existing cards, so typing does not rebuild the DOM or reload images. `renderResources()` rebuilds cards when the language changes or the catalog length changes.

## In-page PDF reader

`scripts/pdf-reader.js` is independent of the rest of the page and is loaded on both pages. It exposes:

- `openPdfReader(url, title, opener, downloadUrl, preview, placeholder)`
- `prefetchPdfEngine()`
- `updatePdfReaderLanguage()`

### Session lifecycle

```text
idle → engine loading → document loading → first page rendered
                                         ↘ outline built in background
     ↘ browser-viewer fallback (load error or 7s watchdog)
     → closed (destroy loading/render work, clear DOM, restore focus)
     → print page snapshot (wait for afterprint, then restore reader)
```

Key invariants:

- `activePdf` points at the current session, or `null` when closed.
- Every `await` continuation verifies `activePdf === session` before touching the DOM.
- A close event that arrives after a rapid reopen must not clear the new session.
- `session.fallback` means the browser iframe owns rendering; the canvas toolbar is hidden.
- `session.page` remains `0` until the first page finishes rendering.
- Preview PDFs (`pdfs/web/*-web.pdf`) feed the canvas reader. The download/print-full links always point at the print-quality file.
- PDF.js module and worker URLs include the site version; a failed engine prefetch resets so a later click can retry.

### Printing

- **Print this page:** renders the current PDF page at up to 2550px, then calls `window.print()`. The print canvas survives until `afterprint` (5-minute fallback).
- **Print full PDF:** opens the print-quality PDF in a new tab without `download`.
- **Download print PDF:** uses the `download` attribute.
- **Certificate:** a separate print sheet; normal page, certificate, and reader print modes are isolated by body classes and `@media print`.

## Offline shell / service worker

`sw.js` is registered from `main.js` as `sw.js?v=<site version>`.

- Cache names include the site version: `bobber-shell-<version>` and `bobber-runtime-<version>`.
- **Shell:** pages, CSS/JS, images, manifest, and the reader’s thumbnail placeholders from `precache.json`.
- **Runtime:** non-precached modules such as `vendor/pdfjs` (trimmed to 160 entries).
- **Never cached:** PDFs, preview PDFs, and the classroom ZIP. Offline mode provides the safety shell, not document downloads.
- Navigation uses network-first; offline fallback ignores query strings so `grown-ups.html?lang=es` still returns the grown-ups page.
- Images use stale-while-revalidate and update the shell copy.
- Activation deletes only this site’s old `bobber-*` caches; CacheStorage is shared by every project on the origin.
- A waiting worker shows an update banner. Refresh activates it and reloads; if no waiting worker remains, Refresh reloads directly.

`npm run update:precache` regenerates the shell list from HTML references and `assets/` images. It intentionally excludes `assets/pdfs/` and `assets/downloads/`.

## Versioning

Every local stylesheet/script reference carries `?v=YYYYMMDDx`. The same version is used by:

- both pages,
- the classroom ZIP link,
- `precache.json`,
- the service-worker registration,
- preview PDF URLs,
- PDF.js module/worker URLs.

Use one command:

```bash
npm run bump:version -- 20261121a
```

It updates the pages, regenerates the precache, and verifies consistency. `npm run check:versions` catches mixed or unversioned references.

## Known limitations

- Offline mode caches the shell and images; PDFs/ZIPs still require a connection.
- The library is rendered by JavaScript; no-JS users cannot browse cards.
- Reader previews are raster images; print PDFs keep the original vector/accessibility content.
- Spanish safety copy and the Spanish interface still need district/fluent review.
- Formal Section 508 and Public Affairs review is external to this repository.
